# NetAuth 개발 기획서

> **프로젝트명:** `NetAuth`  
> **실행 파일:** `NetAuth.exe`  
> **GitHub 저장소:** `netauth`  
> **개발 언어:** C#  
> **플랫폼:** Windows  
> **개발 프레임워크:** .NET (Windows 대상, 구현 시 지원 버전 확정)  
> **프로젝트 유형:** 사용자 세션 기반 백그라운드 자동화 프로그램

## 1. 프로젝트 개요

### 1.1 배경

- 국립창원대학교 네트워크 접근제어 프로그램인 PClient 사용 환경임.
- 컴퓨터 재시작 이후 PClient가 로그아웃 상태로 실행되며, 자동 로그인 설정만으로 인증이 복구되지 않는 문제 존재.
- 외부에서 원격 접속이 필요한 상황에서 PClient 인증이 완료되지 않으면 네트워크 접근 및 원격 연결에 제약 발생 가능.
- Windows가 사용자 입력 없이 **바탕화면까지 진입하는 환경**을 전제로, PClient 로그인 작업의 자동화 필요.

### 1.2 개발 목표

- Windows 사용자 세션 시작 시 `NetAuth.exe` 자동 실행.
- PClient 실행 및 로그인 창 표시 여부 확인.
- **로그아웃 상태에서만** 저장된 계정 정보로 정상 로그인 절차 수행.
- 로그인 결과 확인 및 실패 시 제한된 자동 재시도.
- 별도의 사용자 조작 없이 네트워크 인증이 복구되도록 구성.

### 1.3 범위와 전제

**포함 범위**

- 기존 PClient 로그인 화면을 대상으로 한 GUI 자동화.
- Windows 사용자 로그인 후 자동 실행 및 상태 확인.
- 계정 정보의 안전한 저장과 사용.
- 실행 이력 및 오류 기록.

**제외 범위**

- PClient·학교 네트워크 접근제어의 우회, 비인가 인증, 보안 기능 비활성화.
- CAPTCHA, 다중 인증 등 추가 보안 확인 절차의 우회.
- Windows 로그인 화면에서의 GUI 조작.
- 전원이 완전히 꺼진 PC의 원격 부팅 기능.
- 학교 계정의 비밀번호를 소스 코드, 설정 파일 또는 로그에 평문으로 저장하는 방식.

> **운영 조건:** 학교의 자동 로그인 허용 정책 및 PClient 사용 조건을 우선 확인함. 정책상 제한되는 경우 해당 기능을 구현하지 않음.

## 2. 개발 기술 및 선정 이유

| 구분 | 선정 기술 | 선정 이유 |
|---|---|---|
| 언어 | C# | Windows API 및 데스크톱 자동화와의 연동 용이 |
| 런타임 | .NET (Windows 대상) | Windows 전용 실행 파일 및 배포 지원 |
| GUI 요소 탐색 | Microsoft UI Automation | 로그인 창, 입력란, 버튼 등 접근성 요소 확인 |
| GUI 자동화 보완 | FlaUI 등 .NET 래퍼(필요 시) | UI Automation 기반 탐색·조작 코드 단순화 |
| 자격 증명 보관 | Windows Credential Manager 또는 DPAPI | 비밀번호 평문 보관 방지 |
| 자동 시작 | Windows 작업 스케줄러 | 사용자 로그인 시 실행 및 지연 시작 설정 가능 |
| 기록 | 로컬 구조화 로그 | 인증 상태·재시도·오류 분석 |
| 배포 | `dotnet publish` | PyInstaller 없이 Windows용 EXE 배포 |

**우선 원칙**

1. 화면 좌표 기반 클릭보다 UI Automation 요소 식별 우선 적용.
2. PClient가 UI Automation 요소를 노출하지 않는 경우에만 다른 합법적 GUI 입력 방식 검토.
3. 관리자 권한은 실제 필요성이 확인된 경우에만 요청.
4. 사용자 세션 기반 프로그램으로 설계. Windows 서비스가 직접 로그인 창을 조작하는 구조는 사용하지 않음.

## 3. 전체 동작 구조

```text
[PC 부팅 / 재부팅]
         |
         v
[Windows 사용자 세션 시작]
         |
         v
[작업 스케줄러 → NetAuth.exe 실행]
         |
         v
[PClient 프로세스 및 로그인 창 탐지]
         |
         +------------------------------+
         |                              |
         v                              v
  [이미 인증됨]                  [로그아웃 / 로그인 창]
         |                              |
         v                              v
   [추가 작업 없음]               [자격 증명 로드]
                                        |
                                        v
                                [ID/PW 입력·로그인]
                                        |
                                        v
                                [로그인 결과 확인]
                                        |
                           +------------+------------+
                           |                         |
                           v                         v
                        [성공]                     [실패]
                           |                         |
                           v                         v
                      [상태 기록]           [재시도 제한·오류 기록]
                           |                         |
                           +------------+------------+
                                        |
                                        v
                              [주기적 상태 확인]
```

### 3.1 상태 정의

| 상태 | 의미 | 처리 |
|---|---|---|
| `WaitingForPClient` | PClient가 아직 실행되지 않음 | 짧은 간격으로 재탐색 |
| `CheckingState` | 프로세스·창·인증 상태 확인 중 | 로그인 필요 여부 판단 |
| `Authenticated` | 정상 인증 상태가 확인됨 | 조작 없이 감시 유지 |
| `LoginRequired` | 로그인 창 또는 로그아웃 상태 확인 | 자동 로그인 시작 |
| `LoggingIn` | 계정 정보 입력 및 로그인 요청 중 | 중복 로그인 요청 차단 |
| `RetryPending` | 인증 실패 후 대기 | 제한된 횟수만 재시도 |
| `ManualActionRequired` | 인증 화면 변경, 추가 인증, 계정 잠금 위험 등 | 자동 입력 중단 및 상태 기록 |

**중요:** PClient 창이 존재하지 않는다는 사실만으로 로그인 성공을 판정하지 않음. 실제 인증 상태를 확인할 수 있는 신뢰 가능한 신호를 탐색·검증한 뒤 판정 기준 확정.

## 4. 주요 기능 요구사항

| ID | 기능 | 상세 요구사항 | 우선순위 |
|---|---|---|---|
| FR-01 | 자동 실행 | Windows 사용자 로그인 후 자동 실행 | 필수 |
| FR-02 | PClient 탐지 | 프로세스 및 로그인 창 확인 | 필수 |
| FR-03 | 인증 상태 판정 | 이미 인증된 경우 자동 입력 미수행 | 필수 |
| FR-04 | 자동 입력 | 승인된 정상 로그인 화면에서 ID·PW 입력 및 로그인 요청 | 필수 |
| FR-05 | 보안 저장 | Windows 보호 저장소에 계정 정보 저장 | 필수 |
| FR-06 | 결과 확인 | 성공·실패·확인 불가 구분 | 필수 |
| FR-07 | 실패 대응 | 재시도 간격, 최대 시도 횟수, 중단 조건 적용 | 필수 |
| FR-08 | 로그 | 타임스탬프, 상태 전환, 오류 코드 기록 | 필수 |
| FR-09 | 상태 감시 | 일정 주기로 인증 상태 확인, 필요 시 복구 | 권장 |
| FR-10 | 트레이 UI | 현재 상태·실행/중지·설정 화면 표시 | 추후 |
| FR-11 | 알림 | 연속 실패 또는 수동 조치 필요 상황 안내 | 추후 |

### 4.1 비기능 요구사항

- **안정성:** PClient 실행 지연, 창 전환, 네트워크 일시 단절에 대응.
- **안전성:** 로그인 요청 중복 방지 및 계정 잠금 유발 가능성 최소화.
- **보안:** 비밀번호 마스킹, 로그 내 비밀정보 차단, 필요 최소 권한 적용.
- **유지보수성:** PClient UI 변경 시 창 식별·입력 로직만 수정할 수 있도록 분리.
- **배포성:** 사용자가 추가 Python 환경 없이 실행할 수 있는 Windows용 EXE 제공.
- **가시성:** 실제 인증 결과와 인증 여부를 확인하지 못한 상황을 구분하여 기록.

## 6. 단계별 개발 계획

### Phase 0. 환경·정책 확인

**목표:** 자동화 실행 가능 조건 및 정책적 허용 범위 확인.

- [ ] PClient 버전, 설치 경로, 실행 프로세스명 확인.
- [ ] Windows 부팅 시 사용자 세션이 자동으로 시작되는지 확인.
- [ ] 로그인 창이 일반 사용자 권한에서 조작 가능한지 확인.
- [ ] 학교의 자동 인증·계정정보 보관 정책 확인.
- [ ] 원격 접속 전 필요한 네트워크 연결 조건 확인.

**완료 기준:** 자동화 대상과 실행 조건을 문서화하고, 허용되는 구현 범위 확정.

### Phase 1. PClient UI 탐색 프로토타입

**목표:** PClient 로그인 UI를 C#에서 탐지·조작할 수 있는지 기술 검증.

- [ ] PClient 프로세스 및 최상위 창 탐색.
- [ ] ID 입력란, PW 입력란, 로그인 버튼 식별.
- [ ] UI Automation 지원 여부 및 요소 속성 확인.
- [ ] 로그인 창이 없는 상태와 인증 완료 상태 구분 가능성 확인.
- [ ] 탐지 결과를 비민감 로그로 출력하는 최소 실행 프로그램 제작.

**완료 기준:** 로그인 창과 필수 컨트롤을 안정적으로 식별하거나, 기술적 제약을 명확히 확인.

### Phase 2. 안전한 자동 로그인

**목표:** 정상 로그인 흐름 자동화.

- [ ] Credential Manager 또는 DPAPI 기반 계정정보 저장 구현.
- [ ] 로그인 필요 상태에서만 자동 입력 수행.
- [ ] 로그인 버튼 조작 후 완료 신호 대기.
- [ ] 성공·실패·판정 불가를 구별.
- [ ] 추가 인증 또는 UI 불일치 시 자동 입력 중단.

**완료 기준:** 사용자가 이미 Windows에 로그인한 상태에서 PClient 재인증 시나리오 검증.

### Phase 3. 상태 감시·안정화

**목표:** 상시 사용을 위한 복구 동작 구현.

- [ ] PClient 실행 지연 및 재실행 감지.
- [ ] 감시 주기 설정.
- [ ] 재시도 간격과 최대 시도 횟수 설정(초기 제안: 최대 3회).
- [ ] 계정 잠금 의심·오류 반복 시 자동 시도 중단.
- [ ] 중복 실행과 중복 로그인 요청 방지.
- [ ] 민감정보가 기록되지 않는 오류 로그 적용.

**완료 기준:** 네트워크 지연·로그인 실패·앱 재실행 상황에서 예측 가능한 상태 전환 확인.

### Phase 4. 시작 등록·배포

**목표:** 재부팅 이후 사용자 개입 없이 실행되는 배포본 구축.

- [ ] Release 빌드 생성.
- [ ] Windows 작업 스케줄러에 **사용자 로그인 시** 실행 등록.
- [ ] PClient 시작 지연을 고려한 실행 순서·재탐색 동작 검증.
- [ ] EXE 자동 실행, 로그 위치, 설정 방법 문서화.
- [ ] Windows 재시작 후 로그인 성공까지 종단 간 테스트.

**완료 기준:** Windows 바탕화면 자동 진입 이후 NetAuth 실행 → PClient 인증 완료까지 확인.

### Phase 5. 선택적 기능 고도화

- [ ] 시스템 트레이에 상태 아이콘 표시.
- [ ] 계정정보 변경·삭제용 설정 화면 제공.
- [ ] 수동 재시도 기능 제공.
- [ ] UI 변경 감지와 진단 정보 출력 개선.

### 7.1 주의할 조건

- 작업 스케줄러의 `시스템 시작 시` 트리거와 `사용자 로그인 시` 트리거는 다름.
- PClient 창을 조작하는 GUI 자동화는 일반적으로 **대화형 사용자 세션**이 필요함.
- Windows 잠금 화면 또는 원격 데스크톱 세션 종료 상태에서는 GUI 자동화 성공을 보장할 수 없음.
- Windows 비밀번호 제거 자체가 필수 조건은 아님. 다만 자동 사용자 로그인을 사용하면 물리적 접근 및 계정 보호 위험 증가.
- PC 전원 완전 차단·종료 후 다시 켜는 기능은 NetAuth의 범위 밖임.

## 8. 보안 및 운영 원칙

1. **정상 인증만 자동화:** PClient가 제공하는 로그인 UI와 승인된 인증 절차 사용.
2. **자격 증명 보호:** Windows 보호 저장소 사용. 저장 설정 및 삭제 기능 제공.
3. **비밀번호 비노출:** 소스·Git·설정 파일·명령행 인수·로그에 평문 기록 금지.
4. **오류 시 안전 중단:** 추가 인증, 계정 잠금, UI 불일치, 불명확한 결과에서 무한 재시도 금지.
5. **최소 권한:** 관리자 권한이 필수로 확인되지 않으면 일반 사용자 권한으로 실행.
6. **정책 우선:** 대학 정보전산원 지침에 반하는 자동화 방법 사용하지 않음.

## 9. 배포 계획

- 출력물: `NetAuth.exe` 및 필요한 설정·운영 문서.
- 배포 방식: .NET의 Windows 대상 `publish` 사용.
- 배포 옵션: 초기에는 실행 환경 확인이 쉬운 방식으로 배포하고, 필요 시 단일 파일(`PublishSingleFile`) 및 런타임 포함(`SelfContained`) 방식 적용.
- 자동 실행 방식: 사용자의 **로그온 이후** Windows 작업 스케줄러에서 실행.
- 실행 로그 위치: 사용자별 앱 데이터 폴더(예: `%LOCALAPPDATA%\NetAuth\Logs`).
- 사용자별 설정 위치: 사용자별 앱 데이터 폴더(예: `%LOCALAPPDATA%\NetAuth`).

> 실제 빌드 명령 및 .NET 대상 버전은 개발 PC의 SDK 설치 상태와 의존성 확인 후 확정.

다음 조건을 모두 충족하면 1차 개발 완료로 판정함.

- [ ] `NetAuth.exe` 단독 실행 가능.

- [ ] 성공 여부 판단 및 실패 시 제한된 재시도 가능.
- [ ] Windows 사용자 로그인 후 자동 실행 가능.
- [ ] 재부팅 테스트에서 PClient 인증 자동 복구 확인.
- [ ] 예외 상황에서 안전 중단 및 비민감 로그 기록.

## 11. 착수 시 최우선 확인 항목

**첫 번째 개발 작업은 자동 로그인 코드 작성이 아닌 PClient UI 구조 확인임.**

- PClient의 로그인 창 제목과 실제 프로세스명 확인.
- ID/PW 입력란 및 로그인 버튼이 UI Automation에서 노출되는지 확인.
- 로그인 성공 여부를 구분할 수 있는 접근성 요소 또는 공식 상태 신호 확인.
- 이 결과를 기반으로 구현 가능 범위 및 자동화 방식 최종 선택.

**권장 1차 결과물:** PClient 탐지 결과를 로그에 출력하는 `NetAuth` 콘솔 프로토타입.
